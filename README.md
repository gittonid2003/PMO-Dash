# AOne PMO Command Deck — Cloud Edition

A team-wide, cloud-hosted rebuild of the AOne PMO tracker: real per-person
accounts, one shared workspace everyone sees, accessible from any device
with a browser. See `DEPLOYMENT.md` for getting this live on the internet.

## Architecture, in brief

- **`server/`** — a Node.js (Express) API plus the database layer. Also
  serves the built frontend, so the whole app is one deployable service.
- **`web/`** — the frontend: plain HTML/CSS/JS, no build tooling or
  framework, matching how the rest of this app has always been built.
  `web/dist/` is the assembled, served output — generated by
  `server/scripts/build-web.js`, never edited directly.
- **PostgreSQL** — one database, shared by the whole team. Client photos
  and uploaded documents are stored as real binary data in the database
  itself (not a separate file-storage service), so hosting this needs
  nothing beyond the database and the one web service.

Authentication is real per-person accounts (bcrypt-hashed passwords,
server-side revocable sessions) — not the single shared login the desktop
version used, since this is now reachable from the internet. There's no
open sign-up page by design: the first account bootstraps itself as admin,
and every account after that is created by an admin from Settings → Team
& Access.

## Local development

Requires Node.js and a local PostgreSQL instance.

```bash
cd server
npm install
cp .env.example .env        # then fill in DATABASE_URL and JWT_SECRET
npm run migrate             # creates the tables
npm run seed                # loads the default 9-stage pipeline template
npm run build                # assembles web/dist/ from web/ source
npm start                   # http://localhost:3000
```

`npm start` applies pending database migrations and the repeat-safe seed before
starting the server. Run `npm run migrate` separately when you only want to
manage the database.

Generate a `JWT_SECRET` with:
```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

For local Postgres without SSL, set `DATABASE_SSL=false` in `.env`.

After changing anything under `web/`, re-run `npm run build` (from
`server/`) before restarting the server, or your changes won't show up —
`web/dist/` is a snapshot, not a live link to the source files.

## Run with Docker

Docker Compose runs the app and PostgreSQL together. Create a `.env` file in
the repository root with at least:

```dotenv
POSTGRES_PASSWORD=change-this-local-password
JWT_SECRET=use-a-random-string-of-at-least-32-characters
```

Then build and start the stack:

```bash
docker compose up -d --build
```

Open <http://localhost:3000>. PostgreSQL data is persisted in the host
directory `./data/postgres` by default. Set `POSTGRES_DATA_DIR` in `.env` to
use another host directory. Stop the stack with `docker compose down`; the
database files remain on the host.

## Project structure

```
server/
  index.js              entry point — routes, security headers, static serving
  auth.js                password hashing, session tokens
  db/
    schema.sql           the full table definitions
    migrate.js            runs migrations/ (001 = schema.sql, 002 = On Hold status + photo version)
    seed.js                loads the default pipeline template
    pool.js                 the PostgreSQL connection
  lib/                     async-error shim for Express 4, database error helpers
  middleware/auth.js      session-checking middleware for every protected route
  routes/                  one file per resource (auth, clients, projects, documents, workspace, data)
  scripts/build-web.js     assembles web/dist/ from web/ source

web/
  index.html               the app shell
  store.js                  data layer — talks to the API, holds the in-memory dataset
  auth-ui.js                 login / first-time setup screen
  js/                         rendering + interaction logic, one file per screen
  css/                         styling
  vendor/                      SheetJS (Excel export), loaded on demand
  dist/                        built output — generated, not edited directly

DEPLOYMENT.md              step-by-step guide to getting this live
```
